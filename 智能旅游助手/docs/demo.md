# 答辩演示脚本（8 分钟）

> 目标：在 8 分钟内让人看到「这不是一个聊天框，而是一个能落地的行程系统」。
> 每一段都写了**要说什么**，不只是**点什么**。时间不够时按 ⭐ 顺序删。

---

## 0. 开场前 10 分钟（务必做完）

```bash
cd C:/Users/Administrator/Desktop/go

# ① 起两个进程（SpringBoot 8080 对外 + Python 7861 内部）
bash scripts/start_all.sh          # 保持这个窗口开着，关掉服务就停

# ② 另一个窗口，铺演示数据（含真实模型生成，约 30–60 秒）
.venv/Scripts/python.exe scripts/demo_seed.py
```

`demo_seed.py` 会打印一份摘要，确认四件事都在：

```
✓ 登录已有账号 demo
✓ 清掉 1 份同名旧行程（保证可重复执行）
✓ 新建行程「北京 3 天」  2026-11-03 · 3 天 · 预算 ¥3000
✓ 套用「三天两夜经典」模板  8 项安排
✓ 生成行前装备清单  6 组 / 25 项（来源：forecast）
✓ 记 4 笔账  4/4 成功
✓ 勾选 3 项（1 行前 + 2 行程）

── 演示数据就绪 ─────────────────────────────
  账号      demo / demo123456
  行程      北京 3 天（2026-11-03）
  进度      3/33 项（9%）
  预算      已花 ¥1,421.00 / 剩余 ¥1,579.00（47.4%）
  条目      25 项行前 + 3 天行程
  分享      http://127.0.0.1:8080/s/29ce156d0466549415
```

（数字随日期与天气变化，关键是这四项都在：**有勾选、有 4 笔花费、有分享链接、有 25 项装备**。）

**自检清单**

| 检查 | 命令 / 动作 | 期望 |
| --- | --- | --- |
| 对外入口活着 | 浏览器开 <http://127.0.0.1:8080/> | 官网首页，不是 404 |
| 反代通 | 打开 `/chat.html` 问一句「北京有什么好玩的」 | 有流式输出与引用 |
| 攻略库覆盖 | `curl --noproxy '*' http://127.0.0.1:8080/api/knowledge/coverage` | `count=355`、`full_count=6`、`guided_count=165`、`list_count=184` |
| 索引不是旧的 | 同上，看 `/api/health` 的 `index_stale` | `false` |
| 分享页 | 打开 seed 打印的 `/s/xxxxxxxx` 链接 | 显示行程且标注「只读」 |

> 如果 `start_all.sh` 说端口被占：`netstat -ano | grep -E ":8080|:7861"` 找到 PID 后
> `taskkill //PID <pid> //F`。**不要**跳过这步——旧进程会让新代码不生效，且没有任何报错。

## 1. 一句话定位（30 秒）

> 「用户说『帮我规划北京 3 天，预算 3000』，系统给出的是**一份能勾选、能记账、能导出、能分享**的行程，
> 不是一段需要自己抄下来的文字。」

打开 <http://127.0.0.1:8080/trips.html>，登录 `demo` / `demo123456`。

---

## 2. 行程详情：把「攻略」变成「待办」（2 分钟）⭐

点进「北京 3 天」。按这个顺序指：

1. **顶部**：倒计时（还有 N 天）、进度条 **3/33（9%）**、状态标签。
   > 「进度不是装饰：它来自条目级的完成状态，每条独立可勾。」
2. **行前清单**：**6 组 / 25 项**（证件与票据 4 · 行前预订 6 · 衣物与鞋 5 · 洗护与药品 5 · 电子设备 4 · 季节专项 1）。
   > 「这份清单是按目的地气候和天数算出来的——不是固定模板。`PackingService` 按气温分档，
   > 数据来自 open-meteo 的行程期间预报，所以来源写着 `forecast`；预报拿不到会退化成季节估算。」
3. **每日行程**：第 1 天 / 第 2 天 / 第 3 天，每条带时段与备注（第 1 天是「抵达 → 老城区 → 夜景」这种抵达日节奏）。
4. **预算面板**：已花 **¥1,421 / ¥3,000**，进度条 **47.4%**，下面是分类分布（交通 553 · 住宿 680 · 餐饮 128 · 门票 60）。
5. 勾选任意一条 → 顶部进度条**当场变化**。
   > 「写入是条目粒度：勾一条只 PATCH 一条，没有整篇覆盖接口。整篇 PUT 会让勾到一半的进度归零。」
6. **点「🗺 行程地图」**（这一下最能说明「系统懂行程，不只是懂文字」）：
   > 「同一天同一种颜色，编号就是当天第几站，同一天的点连成线——一眼能看出第 2 天在故宫、
   > 景山一带，不用来回折返。」
   > 「条目名不会跟景点库字字相同，AI 写的是『故宫』，库里有的是『故宫博物院』，这里做了模糊对齐；
   > 对不上的（返程、自由活动、夜市扫街）会**单独列在下面**，不会静默丢掉——丢掉的话你会以为地图漏了地点。」
   > 点任意标记 → 弹出「第几天 · 第几站」。

---

## 3. AI 改行程：这是最像「智能」的一段（2 分钟）⭐

先指出「数据里已经勾好了 2 项行程条目」（第 1 天上午、第 1 天下午，进度 3/33 里含这 2 项），然后输入：

```
第三天想换室内，怕下雨，其他两天不要动
```

点「🤖 按我说的改」。等 10–30 秒。

**要指出两件事**：

1. 只改了第三天，前两天的条目**一字未动**——因为提示词要求「只改提到的那几天」。
2. **刚才勾选的两项，重排后仍是勾选状态**。
   > 「实现上不是靠模型记住，是按标题匹配：旧行程里 `done=true` 的标题集合，
   > 在新结果里重新打上勾。模型重排会换顺序、换措辞，但不能让用户白勾。」

如果现场模型不可用，脚本会返回可读的错误（不是 500），直接说：
> 「AI 侧是独立服务，挂了只降级这一块，行程数据在 SpringBoot 侧不受影响——这正是拆两个后端的原因之一。」

---

## 4. 记账（1 分钟）

在预算面板「记一笔」：分类选「门票」、名称「景山公园门票」、金额 `10`、第 1 天 → 已花从 **¥1,421** 变 **¥1,431**，进度条同步。

> 「金额用 `BigDecimal` + `DECIMAL(10,2)`，不是 double——浮点累加 0.1+0.2 会漂，
> 记账类功能对精度零容忍。分类是固定六类枚举，不允许自由文本，否则统计会碎成一堆同义词。」

---

## 5. 模板 / 分享 / 导出（1.5 分钟）⭐

| 动作 | 点哪里 | 说什么 |
| --- | --- | --- |
| 套用模板 | 动作栏「📋 套用模板」→ 选「三天两夜经典」 | 「模板是 `抵达日 + 中间日循环 + 返程日` 的结构，按天数展开——2 天的行程不会出现第 3 天」 |
| 分享 | 动作栏「🔗 分享」 | 「生成随机 token，可撤销；打开是**只读**页，不暴露账号」 |
| 导出 | 动作栏「🖨 导出」 | 「两种：`.ics` 可导入系统日历；打印版 HTML 走浏览器打印成 PDF——**不在服务端生成 PDF**，中文字体嵌入是另一个工程，而且效果更差」 |

分享链接**新开一个无痕窗口**打开，展示只读态。这一步最能说明「分享不是把 token 拼在 URL 上」。

---

## 6. 回到对话：多 Agent 与 RAG（1.5 分钟）

打开 <http://127.0.0.1:8080/chat.html>，问：

```
成都 3 天怎么安排？预算 2000
```

要指出：

- **协作轨迹**：调度中心先派活，景点顾问 / 美食顾问 / 行程规划师依次接力，能看到谁在做什么；
- **回答带引用**：引用来自本地攻略库（6 城精编 + 其余城市景点清单），不是模型编的；
- **越界会明说**：换成「哈尔滨 3 天怎么玩」→ 系统明确告知攻略库暂未覆盖，不硬编。

> 「覆盖边界是显式声明的：检索层无覆盖就返回空，提示词里注入边界，回答里带脚注。
> 三层都做，是因为静默降级最难查——用户会以为模型在胡说，实际是语料没有。」

> 「工程上有两件事我比较在意：
> ① **回归是 11 组、全离线**（pytest 197 + JUnit 59 + 脚本 489），一条命令跑完；

## 翻车预案

| 现象 | 原因 | 现场处理 |
| --- | --- | --- |
| 页面能开，问一句就降级 | Python 侧的 BGE / torch 没加载起来 | 看 `/api/health` 的 `rag_state`，说「这是依赖层问题，业务链路不受影响」，改演示行程工作台 |
| 行程详情 404 | 线上是旧版单进程（**新接口只在 SpringBoot 侧**） | 确认演示用的是 `start_all.sh` 起的 8080，不是线上域名 |
| AI 改行程转很久 | 模型排队 | 超过 40 秒直接跳过，改说实现原理（按标题保留勾选 + 提示词围栏） |
| 端口被占 | 上次没退干净 | `taskkill //PID <pid> //F`，**必须重启**，否则跑的是旧代码 |
| 网络断 | 天气/模型都要外网 | 天气会退化成季节估算，装备清单仍能出；说明「降级路径是设计的一部分」 |
| **模型整段不可用**（额度用完 / 现场断网） | 聊天、AI 生成、AI 改行程全部失败 | 切到行程页点 **「先看一份示例（北京 3 天）」**：景点名来自本地地图数据、不调模型、不联网，照样能把工作台（行程表 / 行前清单 / 预算 / 导出 / 分享）完整演示一遍 |

| --- | --- |

| 不花额度 | 加 `--no-ai`：只铺模板 + 装备 + 记账 + 勾选，跳过模型生成（约 3 秒） |
| 换城市 | `--city 成都 --days 4 --budget 4500`；只有 6 城有完整攻略，其余城市 AI 段会明说「只有景点清单」 |

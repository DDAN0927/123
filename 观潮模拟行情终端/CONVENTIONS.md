# 口径约定

这份文件里的每一条都对应一个**真实发生过的缺陷**,不是设计原则清单。
写下来的目的只有一个:同一个坑不要踩第二次。

每条格式为「规矩 / 为什么 / 怎么验」。怎么验写不出探针名的,说明这条还停留在口头。

---

## 1. 一条数据,一个来源

### 1.1 价格序列:`series` 是唯一真相

**规矩**:任何需要「历史收盘价」的计算,都必须从 `ensureSeries(s)` 派生。不允许另起一个 seed 造第二条路径。

**为什么**:`ensureDiagCloses` 曾经自己用 `seed = code + 'dc'` 造了 120 根,与图表(1,300 根)的日收益相关系数只有 **-0.067 ~ 0.147** —— 两条独立随机游走。结果 0700 图上 RSI 32.6(偏弱),诊断面板说 55.9(偏强);AAPL 图上 20 日 -7.9%,诊断说 +4.2%(方向相反)。用户不需要懂代码就能发现这个矛盾。

**怎么验**:`verify-diag-source.js` 48 条。分三层 —— 序列层逐位比对、DOM 层读面板数字用同一份序列重算、对照组把旧实现塞回去证明它能变红。

> 附带教训:**另写一份实现**就是分裂的成因。`genSeries` 加 `closesOnly` 选项而不是复制一段循环,代价是函数多一个分支,收益是永远不可能分叉。

### 1.2 聚合:先说清权重

**规矩**:「板块涨幅」「代表指数」这类聚合值,必须在代码注释里写明权重(市值加权 / 等权),并且**同一个概念全局用同一种**。

**为什么**:市值加权与等权在极端分布下能差几个百分点。`boardStats` 用市值加权算 `chg`,同时用等权数「几只上涨」—— 这两个数放在同一张卡片上,读的人会以为是同一套口径。

**怎么验**:暂无探针。改动聚合逻辑时手工对一次「最强板块」与「最大市值成分」是否自洽。

### 1.3 缺失:不说 0,不说 50

**规矩**:算不出来就返回 `null` / `available:false`,界面显示「—」。**不许用 0、50、或任何中性值填充。**

**为什么**:温度计的波动维度旧式 `cl(85 - vAvg*55)` 在均值处得负值,clamp 后**恒等于 4**——等于把「硬编码 64」换成了「硬编码 4」,还把「过热」档(≥80)压成永久不可达(复合分上界 73.75)。一个永远显示 4 分的维度,比显示「—」更糟:它看起来像算过了。

**怎么验**:`verify-thermo-quality.js` 34 条(四维各自 available、权重归一、缺失清单用中文名)。

## 2. 涨跌的定义

**规矩**:`chgPct > 0` 是涨,`< 0` 是跌,`= 0` 是平。**平盘不算涨。**

**为什么**:`boardStats` 里是 `if (s.chgPct >= 0) up++`,温度计里是 `filter(s => s.chgPct > 0)`。同一份数据,两个地方对「上涨家数」给出不同的数。差一只时没人会发现,差多了就是两个真相。

**怎么验**:自检「板块涨跌家数: 平盘不算涨, 三态相加等于总数」—— 构造 2 涨 / 2 跌 / 2 平,断言 `up + down + flat === count`。

**这不是理论问题**:实测全库 10,666 只里 **58 只** `chgPct` 恰好为 0,15 个行业组里 **14 个**至少有一只平盘。「食品饮料」290 只里 1 只平盘 —— 旧实现报「涨 131 / 跌 159」,加起来 290,看着天衣无缝,实际是错的。

> 教训:我第一版在这条注释里写的是「模拟数据几乎不会恰好为 0,这行分支永远不触发」,**纯属推测**,一量就打脸。写「不会发生」之前先数一遍。

## 3. 数据质量信封

**规矩**:任何「多维度打分 / 多项目判定」的面板,必须能说出来**「这一项算不出来」**,并给出行 `available / total / missing / degraded / notes`。

**为什么**:纪律面板 5 条规则里只判得出 3 条时,旧实现显示「3/3 守住」—— 读起来是满分,实际只有 60% 的信息。持仓里有一只查不到价格时,旧实现从总资产里静默扣掉(681,074 → 662,450),界面上一个字都没有,而纪律面板还打绿灯「✓ 止损在位 · 全部在位」——只查了 1 只,报了全部。

**怎么验**:`verify-orphan-holding.js` 52 条、`verify-thermo-quality.js` 34 条、页内自检「有规则缺失时不算满分」。

**粒度**:温度计是**维度级**信封(每维各自 available),持仓面板是**面板级**信封(一个结论 + N 项证据)。两者形状相同、粒度不同,**不要硬合并** —— 合并会把「缺了哪一维」压成「缺了几项」。

## 4. 持仓分两堆

**规矩**:`resolveHoldings()` 把持仓分成「可定价 / 无法定价」两堆,所有面板共用。掉出股票池的持仓**只报成本,不猜价格**。

**为什么**:三条真实 UI 路径(同步东财快照、导入 CSV、加载缓存快照)都会整体替换 `STOCKS` / `BY_CODE`。替换后 `account.positions` 里仍留着旧代码。此前 `renderPortfolio` 与 `accountMetrics` 各自 `if (!s) return null` 跳过 —— 两处过滤,两套结果。

**怎么验**:`verify-orphan-holding.js`。

**出口**:无法定价的持仓可以「按成本注销」(不是「卖出」——没有报价就没有成交价)。注销**不计盈亏**,写入 `side:'close'` 流水,补回账面恒等式。**必须留痕**:现金凭空变多却没有记录,和静默蒸发是同一类问题,只是方向相反。

## 5. 破坏性操作要点两次

**规矩**:任何「一次点击就让数据消失」的操作,必须二次确认 + 超时撤回(4 秒)。

**为什么**:注销孤儿持仓时,点一次就消失的观感和「静默蒸发」一模一样。区别只能在于是不是用户自己按的。这层确认是唯一的安全边界。

**怎么验**:`verify-orphan-holding.js` I 段 —— 点一次断言账面一分不动、4 秒后自动撤回(真等 4.3 秒,假时钟测不到 `setTimeout` 与 DOM 文本的联动)、点两次才执行。

> 附带教训:**`cursor:default` 是视觉,不是行为**。孤儿行标了不可点,但点击委托照样把它当普通行处理 —— 点一下就关掉整个抽屉。

## 6. 可视化

### canvas 不认 CSS 变量

**规矩**:canvas 上取色必须 `getComputedStyle(document.documentElement).getPropertyValue('--x')`,不能直接写 `ctx.strokeStyle = 'var(--ma5)'`。

### 对比度:文本 4.5:1,图形件 3:1,alpha 先合成

**规矩**:新增文字在**亮暗两套主题**下都要实测;半透明(`globalAlpha` / `rgba`)必须先与背景合成再算,不能用名义色值硬算。

**为什么**:MA 三线的注释曾宣称「明暗均 ≥3:1(实测)」而从未实测过 —— 亮底实际是 2.27 / 2.17 / 2.91。另一处 `globalAlpha = 0.85` 把名义 4.22 打成 3.28。

**怎么验**:`contrast.js`(全页扫描)、`verify-ma-contrast.js` 27 条、`verify-orphan-holding.js` G 段。

> 附带教训:**切主题要显式切两次并断言取色不同**。页面初始主题取决于系统偏好,「当前算什么」不能当第一份样本 —— 曾把两次亮色样本标成「暗色/亮色」。

### 表格宽度:`min-width` + `overflow-x:auto` 会把最右列藏起来

**规矩**:放在表格里的关键操作,不要放最右列。

**为什么**:`.pf-table{min-width:420px}` 在 390px 屏上要横向滚动,注销按钮放最右列时只露出半个边框。移到名称列下方才完整可见。

**怎么验**:`probe-mobile.js` + 截图目视。

## 7. 日期

**规矩**:解析日期字符串用 `new Date('2026/11/17')`,不用 `new Date('2026-11-17')`。

**为什么**:后者按 UTC 解释,在 `+08:00` 环境下会倒退一天。`TODAY` 一旦差一天,K 线的最后一根、周月聚合、`dayStamp` 全部错位。

## 8. 探针

### 变红先怀疑探针

**规矩**:探针失败时,先证明「探针测的是它以为在测的东西」,再改代码。

**为什么**:已发生三次 ——
1. 可读性段跑在「恢复股票池」之后,量到的是元素不存在;
2. 修完之后两次取样落在同一主题,标着「暗色/亮色」实际量了同一套;
3. 对账探针首跑 8.5e-6 的权重差,查实是 `liveTick` 在等待期间漂移了 `last` —— 钉死后精确到 1e-16 一致。

### 「相等」类断言要配对照段

**规矩**:凡是断言「A 等于 B」的探针,最好再写一段把**旧实现塞回去**,断言它必须变红。

**为什么**:没有对照段,A 和 B 可能只是「两边读了同一份缓存」。`verify-diag-source.js` 的 C 段就是干这个的(旧实现 52.2 vs 图上 75.1)。

### 一律带 `?api=off`

**规矩**:所有探针都以 `file://...index.html?api=off` 打开。

**为什么**:不带时 `http(s)` 环境下前端会自动探测 `127.0.0.1:8000` 改走后端数据。同一份断言会因为「后端今天有没有在跑」得出不同结果。

### 断言条数不是契约

**规矩**:报告里写「29 → 52」是在说覆盖变多了,不要求任何时刻等于某个数。要的是 **0 FAIL**。

## 9. 部署:能被访问才算交付

### 9.1 三个文件缺一个就等于没部署

**规矩**:后端要能部署,必须同时有 ① `requirements.txt`(钉版本) ② 进程入口(`Procfile` / `render.yaml` / `Dockerfile` 任一) ③ 鉴权开关。三者缺一,"前后端分离"只在本机成立。

**为什么**:此前四条待办(依赖声明 / 进程入口 / 鉴权 / 持久化)长期挂在 README 里没做,但对外表述一直是"已完成前后端分离"。换台机器 `pip install` 都不知道装什么版本;**端口写死 8000 或绑 127.0.0.1 在云端是 502,日志里看不出来**;没有鉴权就是把数据送上网。

**怎么验**:`verify-deploy.js` 的 A 段 20 条,直接读制品文件断言内容(而且断言 `healthCheckPath` 必须是真实存在的路径 —— 写错平台会反复重启)。

### 9.2 白名单会掩盖鉴权失败

**规矩**:探活端点开放鉴权时,**前端不能靠它判断"有没有权限"**。必须看业务接口的失败原因,全部 401 才叫没权限。

**为什么**:`/api/health` 在鉴权白名单里永远 200。于是没带 token 时前端先是"探测成功",接着 31 个行情请求全 401,被笼统判成 `degraded`(数据降级)。"没权限"和"上游坏了"混成一件事,排查会从错误的方向开始。

**怎么验**:`verify-deploy.js` D1(无 token 标 `denied`)/ D5~D7(带 token 标 `server` 且 31 只全同步)。

> 状态四态:`server` / `local` / `degraded` / `denied`。少一个,就有一类故障说不清原因。

### 9.3 断言不许整文件搜关键词

**规矩**:断言配置/制品文件时,只检查**承载语义的那一行**(如 `CMD` 行、`healthCheckPath:` 行),不要在全文里 `includes('--reload')`。

**为什么**:`A17` 一开始是全文搜,结果被我自己**解释为什么不用 `--reload`** 的注释判红。写清楚理由反而让测试失败 —— 这会逼着人删注释,是本末倒置。

**怎么验**:`verify-deploy.js` A17 只看 `CMD` 行。

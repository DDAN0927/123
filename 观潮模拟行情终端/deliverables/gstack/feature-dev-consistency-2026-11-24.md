## 一、孤儿持仓的出口:按成本注销

### 为什么不能叫「卖出」

上一轮把「掉出股票池的持仓」从静默蒸发改成显式披露,但没给出路:标的已不在 `BY_CODE`,详情页打不开、卖不掉,用户只能**重置整个账户** —— 连正常持仓和历史一起清掉。

「平仓」这个词在这里有陷阱。可选做法只有三种:

| 做法 | 结果 |
|---|---|
| 按现价卖出 | 没有现价,编一个就是造假 |
| 按 0 元清仓 | 等同于全部亏损,账面凭空多一笔巨亏 |
| **按成本价注销** | 不计盈亏,现金按成本退回;**不声称这是市场成交** |

只有第三种不编造数字。所以按钮文案是「按成本注销」,不是「卖出」—— 探针里有一条专门断言这一点(`!/卖出/.test(btnTxt)`)。

### 记账口径

```
现金 += 成本 × 数量
删除持仓
写入 { side: 'close', qty, price: 成本, fee: 0, chg: null }
realized 不变
```

注销后账面恒等式被补回去:`cash + mv` 重新等于 `初始资金 + 已实现 + 浮动`。

**注销前**这部分成本悬在账外 —— 既不进 `mv` 也不进 `realized`。这正是它必须留痕的原因:**现金凭空变多却没有记录,和静默蒸发是同一类问题,只是方向相反。**

实测(600519 + NVDA 各 100 股 + 现金 50 万,同步 A 股快照后注销 NVDA):

| | 注销前 | 注销后 |
|---|---|---|
| 现金 | 500,000 | **518,640** |
| 总资产 | 662,450 | **681,090** |
| `realized` | 0 | **0** |
| 持仓表 | 2 行(1 行标注无法定价) | 1 行 |

### 二次确认是这里唯一的安全边界

一次点击就让持仓消失,和「静默蒸发」的观感一模一样。区别只能在于是不是用户自己按的:

- 第一次点击 → 按钮变「再点一次确认」,虚框 + 底色,账面**一分不动**;
- 4 秒不操作自动撤回(防手滑隔一会儿再点到同一位置);
- 第二次点击才执行。

探针真等 4.3 秒验证撤回(假时钟测不到 `setTimeout` 与 DOM 文本的真实联动)。

### 顺带修掉的行为缺口

孤儿行原来命中 `#portfolio` 的 `[data-code]` 委托:

```js
const row = e.target.closest('[data-code]');
if (row) { closePortfolio(); setTimeout(() => openDrawer(code), 160); }
```

点一下就**关掉整个持仓抽屉**,然后 `openDrawer` 一个 `BY_CODE` 查不到的代码。上一轮只加了 `cursor:default` —— 那是视觉,不是行为。

这个缺口是探针报 `element is inert` 才暴露的:注销按钮就在那一行里,点按钮等于顺带关面板,第二次点击落在 `inert` 的 `<aside>` 上,Playwright 一直等不到可点。

### 按钮位置:从最右列移到名称列

`.pf-table` 有 `min-width:420px` + `overflow-x:auto`。390px 屏上最右列**在视口外** —— 把唯一出口放在要横向滚动才能看见的地方,等于没有出口。

第一版就放在最右列,截图一看只有半个 `[` 露在边缘。移到名称下方后完整可见,跨列文字也改左对齐(孤儿行没有数值,右对齐会把它推到表格最右端)。

## 二、诊断与图表同源

### 复现

`ensureDiagCloses` 自己用 `seed = code + 'dc'` 另造一条 120 根随机路,与图表(`ensureSeries` 的 1,300 根)毫无关系。两条路的**日收益相关系数实测 -0.067 ~ 0.147**。

用户能当场看见:

| 标的 | K 线图上看 | 诊断面板说 |
|---|---|---|
| 600519 | 近 20 日 **+10.9%** | **+1.4%** |
| 0700 | RSI **32.6**(偏弱) | RSI **55.9**(偏强) |
| AAPL | 近 20 日 **-7.9%** | **+4.2%**(方向相反) |
| 300750 | **-2.6%** | **+9.2%** |

上一轮刚修过「文案说近 120 根、实际算 1300 根」的口径不实。这个更严重:不是文案问题,是**两个价格世界**。

### 改法

`genSeries` 加 `closesOnly` 选项:同一个 seed、同一段 gauss、同一次 rescale,只是不构造 OHLCV 对象。

刻意复用同一函数而不是另写一份 —— 因为「另写一份」正是这次分裂的成因。`ensureDiagCloses` 于是变成:

```js
if (s.series && s.series.length) {           // 图表已建:直接切末 120 根
  s._dc = s.series.slice(-120).map((d) => d.c);
} else {                                      // 图表未建:走同一算法的收盘价快捷路径
  s._dc = genSeries({ ...s, price: s.last }, { closesOnly: true }).slice(-120);
}
```

`ensureSeries` 生成序列后顺手把 `_dc` 对齐过去,避免「`_dc` 是旧 `last` 算的、`series` 是新 `last` 算的」这种半新半旧状态。

### 影响面(200 只按市值取的样本)

| 指标 | 结果 |
|---|---|
| RSI 状态分类变化 | **159/200(79.5%)**,平均绝对变化 **20.4 点** |
| 止损价平均相对偏差 | **4.04%** |
| 止损破位判定翻转 | **0 例** |

破位 0 例是因为 `stop` 的裕度(现价的 85%~97%)大于这 4% 偏差。所以在只关心「止损在位 / 破位」的纪律面板上,**结论不会因为这次修正突然翻转** —— 变的是诊断面板里那些具体数值,而它们原来算在一条不存在的价格路径上。

### 性能

`closesOnly` 省掉对象构造:120 只标的实测 **208ms → 49ms**。`renderSignals` 在首屏对 120 只逐个 `computeDiag`,这是唯一一处批量调用。

### 两个坑写进了 README

1. **探针必须带 `?api=off`**。不带时,`http(s)` 环境下前端会自动探测 `127.0.0.1:8000` 改走后端数据,同一份断言会因为「后端今天有没有在跑」得出不同结果。
2. **断言条数不是契约**。`29 → 52` 不是回归,是覆盖变多。要的是 0 FAIL。

### 约定里最重要的一条

**探针变红先怀疑探针。** 本轮和上一轮共发生三次:

1. 可读性段跑在「恢复股票池」之后,量到的是元素不存在;
2. 修完之后两次取样落在同一主题(页面初始主题随系统偏好),标着「暗色/亮色」实际量了同一套;
3. 对账探针首跑 8.5e-6 的权重差,查实是 `liveTick` 在等待期间漂移了 `last`。

还有一条:**给「相等」类断言配对照段**。`verify-diag-source.js` 的 C 段会把旧的独立随机序列塞回去,断言面板数字必须因此变红 —— 没有这一段,A 和 B 可能只是「两边读了同一份缓存」。

## 五、已知局限

1. **注销价就是成本价**,不是市场价。没有报价就是没有报价 —— 这条会一直成立。
2. **注销后如果标的回到池子里**,不会自动"还原"持仓。流水里留着记录,用户要重建就按现价买入。
3. **诊断序列与图表序列现在同源,但图表序列本身是合成的**(`genSeries` 的 1,300 根随机游走)。同源不等于真实 —— 只是"两个地方说的是同一件事"。
4. `stop` 的裕度设计(现价 85%~97%)意味着**止损永远不可能因为 4% 的序列偏差而翻转**;这既是这次影响面小的原因,也说明纪律面板对数据源变化不敏感。将来接真实行情时,这个裕度可能要重新校准。
5. 后端接口**仍无鉴权**,只适合本机/内网;线上站点**仍是旧版**,部署被账号权限卡住。

# 持仓「无法定价」与三处结论面板的数据质量信封

日期:2026-11-24 · 分支 `master` · 提交 `d4ade34` → `70fd2ab` → `cf10b55`

本轮目标是上一轮留下的选项 ①:「把 data_quality 信封从温度计借到持仓/交易」。动手前先按老规矩量了数据覆盖度,结论是**这一轮不该动后端**;真正值得修的是另一个问题 —— 持仓会从总资产里静默蒸发。

---

## 一、先说没做什么,以及为什么

| 检查项 | 实测 |
|---|---|
| 后端可服务标的 | `/api/market/universe` = **31 只**(CN 12 / US 10 / HK 6 / CRYPTO 3) |
| 前端可持仓标的 | 全量 **5,212 只** + 导入 CSV 任意代码 |
| 后端对非精选标的 | `GET /api/market/kline?code=000001` → **404 标的不存在** |

持仓/分散度/纪律复盘的计算依赖「任意一只持仓的序列与快照」。后端只有 31 只,搬过去就是「同一功能两种口径」—— 与温度计那次同一条理由,而且这次差距更极端(0.6% 覆盖)。

**结论:计算留在数据所在的一侧,后端不动。** 这一轮的工作全部在前端,是把「数据质量信封」当作一种**规矩**推广到持仓域,而不是把代码搬到更"正规"的架构层。

## 二、复现:一个真实可达的数据蒸发

三条 UI 路径都会**整体替换** `STOCKS` / `BY_CODE`:

| 路径 | 函数 |
|---|---|
| 同步东财/新浪真实快照(仅 A 股) | `resetUniverseTo()` |
| 导入 CSV 行情快照 | `applyImportedUniverse()` |
| 刷新时加载缓存快照 | `loadSnapshotIntoUniverse()` |

替换后 `account.positions` 里仍留着旧代码,而 `BY_CODE` 查不到它。持有美股再同步 A 股快照,NVDA 当场变孤儿。

**场景**:600519 + NVDA 各 100 股 + 现金 50 万,然后 `resetUniverseTo(仅 CN)`:

| | 改前 | 改后 |
|---|---|---|
| 总资产 | 681,074 → **662,450** | 681,074 → 662,450(带说明) |
| 持仓表 | 2 行 → **1 行** | 2 行(孤儿行标注) |
| 界面提示 | **无** | 「1/2 只持仓可定价 · 1 只无法定价(成本 ¥18,640),未计入总资产与市值 · NVDA」 |
| 纪律·止损 | **✓ 止损在位 · 全部在位** | 「— 止损在位 · 已验 1/2 只」 |

金额本身没错 —— 没有价格就不该编一个价格。错的是**一句话都不说**。而纪律面板那句绿灯最糟:它只查了 1 只,却报了「全部」。

补充一点:`sanitizeState()` 只按 `CODE_RE` 校验代码格式,不校验是否在股票池内,所以孤儿持仓**刷新后仍在**。这不是一次性视觉故障。

## 三、改了什么

### 1. 一个入口,两堆持仓
`resolveHoldings()` 把持仓分成「可定价 / 无法定价」,`accountMetrics()` 与 `renderPortfolio()` 共用。此前两处各自 `if (!s) return null` 跳过 —— 这既是蒸发的来源,也是「表格里的市值」与「总资产里的市值」可能不一致的来源。孤儿**只报成本,不猜价格**。

### 2. 面板级信封
```js
dataQuality(available, total, { notes })  // → {available,total,missing,degraded,notes}
dqLineHTML(key, text, degraded)           // → 带 data-dq 的可见行
```
形状对齐后端 `core/envelope.py`。注释里写清:温度计用的是**维度级**信封(每维各自 available),粒度不同,别硬合并 —— 免得下一个人"统一"出个四不像。

### 3. 三处面板的口径校正

**分散度**
- 权重只覆盖可定价市值 → 面板写明,并标「+N 未定价」;
- 相关系数覆盖率(`x/y 对可算`)与窗口根数改为**按实际算出来的值**报,不再写死「近 120 根」;
- 空态不再只说「持仓不足 2 只」,而是「可定价持仓不足 2 只」+ 孤儿只数。

**纪律复盘**(三处)
- **评级分母**:5 条规则只判得出 3 条时,旧实现显示「3/3 守住」,读起来是满分。现在带「· 2 项缺失」,且**完美判定要求全项可判** —— 否则不给百分比、不给 `is-pass`。
- **追高规则**:旧实现「有一笔缺 chg 就整条废掉」,19 笔有效样本白扔;现在按可用子集判定并标注覆盖率(`6/8`),但可用样本不足 5 笔仍判缺失 —— 不拿 2 笔硬判「50% 追高」。
- **止损规则**:诊断止损取不到时判缺失,不再当成「在位」。

### 「只加语义、没动数值」的证明
`verify-pf-parity.js` 用 `git HEAD` 的旧文件与新文件跑同一组持仓,逐项对账:

```
HHI            0.3139318720418619  vs  0.3139318720418619
有效持仓        3.185404506703457   vs  3.185404506703457
相关矩阵        逐格一致(null 位置也一致)
五条规则        ｜不追高=1/6 笔追高/true｜止损在位=全部在位/true｜频率节制=今日 6 笔/true｜单票 ≤40%=42%/false｜单行业 ≤50%=42%/true
评级            {"txt":"4/5 守住","cls":"is-fail","pct":0.8} 两侧一致
```
样本刻意落在**全项可判**状态(6 笔带涨幅成交 + 4 只可定价持仓),因为本轮有意修改的是「缺失时的表现」,不是「齐全时的数值」。

### 探针自身出过两次错(都当场修掉)
1. `verify-orphan-holding.js` 的可读性段跑在「恢复股票池」之后,量到的是「元素不存在」;
2. 修完后两次取样落在同一套主题(页面初始主题取决于系统偏好),暗色标签下量的其实是亮色 —— 现在显式 `setTheme()` 两次,并加一条「两次取色必须不同」的自证断言。
3. `verify-pf-parity.js` 首跑出现 8.5e-6 的权重差,查下来是 `liveTick` 在等待期间漂移了 `last/chgPct`,把价格钉死后精确到 1e-16 一致。
